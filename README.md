# Bitcoin Z-Score Strategy

A Python-based quantitative trading application that uses Bitcoin market data from the Coinbase API to identify statistically high and low price conditions using Z-Score analysis.

The application combines **real-time Bitcoin price analysis**, **rule-based trading recommendations**, and a **historical backtesting module** with performance and risk metrics including Sharpe Ratio and Maximum Drawdown.

## Overview

The application evaluates the current Bitcoin price relative to its recent historical price distribution.

A Z-Score is calculated as:

**Z-Score = (Current Price − Mean Price) / Standard Deviation**

The resulting value is used to determine whether the current Bitcoin price is relatively high, low, or within its recent historical range.

### Signal Logic

| Z-Score     | Interpretation                        | Trading Signal |
| ----------- | ------------------------------------- | -------------- |
| Z < -1      | Price significantly below recent mean | BUY            |
| -1 ≤ Z ≤ +1 | Price within recent range             | HOLD           |
| Z > +1      | Price significantly above recent mean | SELL           |

The application allows the user to select either **BUY** or **SELL** analysis through a graphical user interface.

## Real-Time Market Analysis

The application retrieves live Bitcoin/USD market data using the Coinbase API.

For the real-time analysis:

* Current Bitcoin/USD spot price is retrieved from Coinbase.
* The most recent 24 hourly closing prices are collected.
* The rolling mean and standard deviation of these prices are calculated.
* A Z-Score is calculated for the current market price.
* The application generates a rule-based BUY, SELL, or HOLD recommendation.
* Results are displayed directly in the graphical interface.

## Backtesting

The application also includes a historical backtesting module using daily Bitcoin/USD candle data.

The backtest:

1. Retrieves historical daily Bitcoin prices from Coinbase.
2. Uses a 7-day rolling window to calculate the mean and standard deviation.
3. Calculates the Z-Score for each subsequent observation.
4. Opens a simulated position when Z-Score falls below -1.
5. Closes the position when Z-Score rises above +1.
6. Tracks simulated profit and executed trades.
7. Calculates risk-adjusted performance metrics.

The backtest uses an initial simulated capital of **$10,000**.

## Performance Metrics

The application calculates:

### Total Profit

The cumulative simulated profit and loss generated by the strategy.

### Sharpe Ratio

The Sharpe Ratio is calculated from the simulated daily portfolio returns and annualised using a factor of √365.

### Maximum Drawdown

Maximum Drawdown measures the largest percentage decline from a previous portfolio peak during the backtest.

### Executed Trades

The application records the number of position entries and exits generated by the trading rules.

## Application Architecture

The application uses separate threads for market-data retrieval and backtesting so that network requests and calculations do not block the graphical user interface.

### Main Components

**`widget.py`**

Contains the main application logic, including:

* Real-time market-data retrieval
* Z-Score calculation
* Trading signal generation
* Historical backtesting
* Sharpe Ratio calculation
* Maximum Drawdown calculation
* PySide6 GUI interaction

**`PriceFetcherThread`**

Retrieves current Bitcoin/USD price data and recent hourly candles from Coinbase and calculates the current Z-Score.

**`BacktestThread`**

Retrieves historical daily Bitcoin data and performs the rule-based backtest.

**`ui_form.py`**

Contains the Python implementation of the Qt Designer interface.

**`form.ui`**

Contains the graphical user-interface layout created using Qt Designer.

## Running the Application

Clone the repository and install the required Python dependencies:

```bash
pip install -r requirements.txt
```

Then run:

```bash
python widget.py
```

The application requires an active internet connection because Bitcoin market data is retrieved from the Coinbase API.

## Limitations

This project is intended as a quantitative modelling and research exercise rather than a live trading system.

The current implementation does not account for:

* Transaction costs
* Slippage
* Position sizing
* Leverage
* Short positions
* Portfolio diversification
* Out-of-sample testing
* Walk-forward optimisation

The historical backtest is based on a limited historical data window and should therefore not be interpreted as evidence of future trading performance.
